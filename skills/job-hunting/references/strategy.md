# Strategy — the Strategist role

Decide what to aim for before anything is searched or written: one
positioning line, an honest level, the adjacent roles worth a look, a
sustainable cadence, and 15–25 target companies with a referral path each.
Record it all in profile §1, profile §2 and profile §8 so no role re-asks
it. Every claim follows `facts-policy.md`.

## 1. Intake — one batch

Ask only what the profile lacks, with options to pick: **area(s)** from
the career map (§4) — a person can span two; **primary stack / tools**;
**target seniority** (junior / mid / senior / staff / lead / manager); a
**lean** toward or away from a specialization; **runway** (under 3 months
/ 3–6 / over 6); **hours a week** for the search. Write the answers to
profile §2 (Desired role(s), Tech sub-domain(s), Main stack / tools,
Target seniority), runway to profile §1 Urgency, and hours a week on the
profile §8 "Weekly application cap:" line (e.g. "12 — 8 h/week").

## 2. Positioning through-line

One line: **"a [X] who does [Y] and delivers [Z]"** — X is the target
title at the level §3 supports; Y the domain, stack or problem type the
target postings share; Z an outcome proven in profile §5
(`facts-policy.md`). Example: "a backend engineer who builds payment APIs
in Go and cuts failed transactions". Record it in profile §8 One-line
identity; it opens the resume summary, the LinkedIn headline and About
(`profile-optimizer.md`), "tell me about yourself" and every outreach
message. No sourced Z → ask for one before using the line.

## 3. Level check

1. Sum dated experience from profile §5 conservatively: overlapping roles
   count once; internships and part-time work are listed separately. If
   profile §1 "Years of experience" disagrees, flag it and use the lower
   figure (SKILL.md memory rules).
2. Read the years asked and the responsibilities in 5–10 target postings
   (saved `postings/`, a Scout shortlist, or pasted text).
3. Compare scope, not titles: team size, ownership, design decisions,
   on-call, stakeholders.
4. Verdict: **on-level** (years and scope met) · **stretch** (one step up,
   one or two gaps) · **reach** (years or scope clearly short) → aim one
   level down, or go through a bridge role from §4.

State the verdict with its evidence line; write the level to profile §2
Target seniority.

## 5. Cadence contract — record it in profile §8

Agree these, then write them on the profile §8 lines "Weekly application
cap:" and "Weekly outreach target:":

- **Cap: 10–20 targeted applications a week.** 11–20 applications → ~9%
  interview rate, 100+ → ~2.6% (Huntr Q1 2026, 140k applications); 66% of
  offers land within 50 applications (Huntr Q1/Q2 2026).
- **Outreach target**: a weekly touch count (e.g. 6), 60/40 outreach to
  applications by time spent; the touches follow `networking.md`.
- **Pacing** — the ~90-day expectation, batch-and-rest, rest weeks and
  runway-aware urgency: agree them from `pipeline.md` §6.
- **One shot per company** per search cycle (`sourcing.md` §3).

## 6. Target list — 15–25 companies

1. Gather candidates: profile §2 Dream companies and Target industries,
   profile §3 company size, companies that recur in the Scout's
   shortlists, and employers posting the target role repeatedly.
2. Tier them: **dream** (a reach on level or brand) · **realistic**
   (on-level — most of the list) · **fallback** (on-level, lower bar, still
   passes profile §3).
3. Drop any that fail profile §3 dealbreakers or the legitimacy checks
   (`sourcing.md` §5).
4. Attach a referral-path note to each from the referral map
   (`networking.md` §2): "alumni ×2", "ex-colleague [name]", "TA search
   only".
5. Record on the profile §2 "Target list:" line in three tiers —
   `Dream: …`, `Realistic: …`, `Fallback: …` — each company with its note
   in parentheses. People found go to contacts (`networking.md` §4). The
   weekly outreach target goes to listed companies before they post.

## 7. When to revisit

- The funnel shows the **targeting** leak — response under 10% after 10+
  sent (`tracker.py funnel`; chat mode: by hand, `pipeline.md` §5).
- The Scout keeps returning the same knockouts or an empty main table
  (`sourcing.md` §7), or the user rejects most shortlisted rows.
- Runway drops under 3 months, or new evidence changes the level check.

Re-run §3 and §4, then the target list. Change one thing and let a week of
numbers test it. Workspace mode: edit `profile.md` in place and end with
the `saved:` line. Chat mode: regenerate the profile block.
