# v5.3 plan — porting from MadsLorentzen/ai-job-search (R&D 2026-07-17)

Reviewed https://github.com/MadsLorentzen/ai-job-search (23k stars, MIT, active
2026-07): a *local* Claude Code job-search rig — portal-scraper CLIs (bun),
LaTeX CV pipeline with drafter→reviewer→PDF-inspect→ATS-verify loop, CSV
tracker, HTML dashboard. Author used it to land an AI-engineer role (69 apps →
20 interviews → 1 offer).

**Relationship to job-hunter:** complementary, not competing. Theirs automates
*on your machine* (scraping, files, tracking); ours coaches *in claude.ai*
(SEA market depth, offer/interview/profile coaching). Already covered by us,
don't port: rank/fit-scored shortlist, interview prep, company research,
salary handling, outcome/funnel tracking, honesty guardrails.

## Done today (not in this repo)

Their rig is cloned at `~/ai-job-search`, Danish portals disabled

## Port into the skill (v5.3), ranked by value/effort

1. **Referral contact links** (their scraper step 4.5) — for every
   high/medium-fit job in a shortlist, emit two LinkedIn people-search URLs
   (`?keywords=<company> recruiter` and `<company> <role keyword>`). Pure URL
   construction, zero deps, SEA hiring is referral-heavy. → job-search section
   of `SKILL.md`.
2. **ATS text-layer verification** (their `/apply` step 7) — after
   resume-builder emits .docx/PDF, re-extract the text in the code sandbox
   (pypdf/python-docx), verify contact details are literal text, reading order
   sane, then score JD keyword coverage on what a parser actually sees. Gaps
   reported honestly, never stuffed. → new final step in
   `references/resume-builder.md`.
3. **Reviewer pass** (their drafter-reviewer split) — before generating final
   files, a mandatory reviewer-hat critique: missed JD keywords, generic
   phrasing, weak framing, cover-letter/CV dependency check. Chat skill has no
   subagents; a structured checklist pass captures most of the value.
   → `references/resume-builder.md`.
4. **Upskill heatmap** (their `/upskill`) — aggregate real gaps *across* all
   pipeline JDs (not per-JD like today), output a prioritized gap heatmap +
   learning plan with searched resources and time estimates.
   → extend `references/jd-match.md` with a cross-JD mode; soft-skills coach
   already owns the soft half.
5. **Profile expansion** (their `/expand`) — during intake/profile-optimizer,
   web-search the candidate's public links (GitHub, portfolio) and add
   discovered skills with a source tag. → `references/profile-optimizer.md`.
6. **Outcome-calibrated search** (their `/outcome` loop) — funnel review's
   one-change recommendation may also adjust saved search criteria weights
   based on which applications actually got interviews. → funnel section,
   `SKILL.md`.
7. **Funnel dashboard artifact** (their `/html-report`) — optional: render the
   profile's pipeline table as a self-contained HTML artifact (stat cards +
   funnel chart) at funnel-review time.

Skip: LaTeX pipeline (needs local toolchain; .docx flow is already ATS-safe
for SEA), portal CLIs inside the skill (claude.ai can't run bun — the local
rig covers this), CSV tracker (profile §pipeline is the tracker).
